# デザイン指示: launchd 定期ジョブの状態表示（#14）

Claude のチャットで、既存のアーティファクト「thoth — アプリ管理 UI プロトタイプ」（#8）に追記・更新するための指示。デザインの参照方法は `CLAUDE.md` の「画面デザインの実装ルール」を参照。更新後は `CLAUDE.md` のデザイン URL・ファイル一覧も更新する。

```
既存のアーティファクト「thoth — アプリ管理 UI プロトタイプ」の【アプリ一覧】に、launchd 定期ジョブ(kind: scheduled、例: deep-tracker の fetch / summary / backup)の状態表示を追加してください(既存のレイアウト・配色・操作は変えず、追記のみ)。【前提】定期ジョブは常駐せず、ポートやプロセス生存では判定できません。backend は「最終実行時刻」「直近の終了コードによる成否」「実行間隔の期待値(expected_interval)を超えて実行されていないか」で状態を返します。状態は7種類: ok=正常(直近の実行が成功) / running=実行中 / failed=失敗(直近の終了コードが0以外。異常扱い) / overdue=遅延(最終実行が期待間隔×1.5を超えて古い。異常扱い) / never=未実行(まだ実行された形跡がない) / unloaded=未登録(launchdに登録されていない) / unknown=不明(取得できない)。各ジョブには、スケジュールの説明(例:「毎日 03:00」)、最終実行時刻(相対表示+絶対時刻)、終了コード(失敗時のみ)、期待間隔、メッセージ(例:「最終実行が期待間隔(24時間)を超えています」)が付きます。定期ジョブには起動/停止/再起動の操作はありません(現状どおり操作不可)。【必要な要素】1)今は「未対応」扱いになっているサービス行を、定期ジョブ用の行に置き換える: 種別が分かる表示(定期ジョブ)+状態バッジ(正常/実行中/失敗/遅延/未実行/未登録/不明。色だけに頼らずアイコン+文言。失敗と遅延は異常として目立たせる)+スケジュール説明+最終実行(「3時間前」など。ツールチップ等で絶対時刻)+メッセージ(長ければ省略)。 2)アプリカードの全体状態への反映: 定期ジョブが失敗または遅延のとき、プロセス系の異常と同じ扱いでカード上に気づける警告を出す(既存の異常アラートの枠組みを流用)。定期ジョブは「稼働中/停止中」の集計には含めない。 3)状態の取得失敗時は、一覧の操作は継続でき、定期ジョブの表示のみ「取得できません」とする。 4)既存の定期更新(5秒)に同期して更新される。更新中のチラつきを避ける。 5)モバイル(375px)とデスクトップの両方、アクセシビリティ(キーボード操作・focus-visible)を満たす。【出力】既存のモックデータに、正常・実行中・失敗・遅延・未実行・未登録・取得できない の各ケースを足し、表示が実際に切り替わる状態にしてください。
```

## 実装時の注意

- モックのダミーデータ・デモ用スイッチは実装に含めない。データは `GET /api/scheduled`（全 scheduled サービスの状態）から取得する。
- 見た目は cosmic-ui のコンポーネントに従う（値はデザインから移植しない）。
