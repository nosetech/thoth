# デザイン指示: ダッシュボード画面（#58）

Claude のチャットで、既存のアーティファクト「thoth — アプリ管理 UI プロトタイプ」（#8）に追記・更新するための指示。デザインの参照方法は `CLAUDE.md` の「画面デザインの実装ルール」を参照。更新後は `CLAUDE.md` のデザイン URL・ファイル一覧も更新する。

```
既存のアーティファクト「thoth — アプリ管理 UI プロトタイプ」のナビ項目「DASHBOARD」を押したときに表示される【ダッシュボード画面】を追加してください(既存のアプリ一覧・配色・操作は変えず、追記のみ。ナビの DASHBOARD が今は画面を持たないので、そこに画面を割り当てる)。ダッシュボードは「参照中心」で、起動・停止・再起動などの操作は置かず、詳細・操作は【アプリ一覧】(APPS)へ誘導します。【表示内容】1)全体サマリ: 登録アプリ数、実行中 / 停止中 / 一部起動 / エラーの件数(アプリ一覧と同じ状態の定義・集計。定期ジョブは稼働中/停止中の集計に含めない)。 2)要対応: エラーのアプリ、ヘルスチェック異常のサービス、定期ジョブの失敗・遅延、自動再起動の状況(再起動中・上限到達など)を、対象のアプリ名・サービス名・状態バッジ(アイコン+文言)・メッセージ付きで並べ、各行から APPS へ遷移できる。要対応が無いときは「要対応はありません」と表示。 3)ヘルスチェックの直近状態: サービスごとの最新結果(正常/異常/不明)と直近履歴の小さな表示(色だけに頼らずアイコン+文言)。 4)アプリごとの状態の一覧(カードまたは行): アプリ名、全体状態バッジ、サービス数・稼働数、要対応の有無、APPS への導線。 5)画面状態: 通常 / 読み込み中(スケルトン) / 空(アプリ未登録。config/apps.yaml への案内) / エラー(backend に接続できない。再試行ボタン)。一部の情報(ヘルスチェック・定期ジョブ・自動再起動)だけ取得できないときは、該当ブロックのみ「取得できません」とし画面全体は壊さない。 6)既存の5秒ポーリングに同期して更新(タブ非表示中は停止、最終更新・一時停止は既存のヘッダ表示を流用)。更新中のチラつきを避ける。 7)モバイル(375px)とデスクトップの両方、アクセシビリティ(キーボード操作・focus-visible)を満たす。【出力】既存のモックデータとデモ用スイッチを流用し、通常・読み込み中・空・エラー・一部取得失敗の各状態が実際に切り替わるようにしてください。
```

## 実装時の注意

- モックのダミーデータ・デモ用スイッチは実装に含めない。データは `GET /api/apps`、`/api/apps/{id}/status`、`/api/service-health`、`/api/scheduled`、`/api/auto-restart` などの既存 API から取得する（新規の集計 API は作らない）。
- 見た目は cosmic-ui のコンポーネントに従う（値はデザインから移植しない）。
