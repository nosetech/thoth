# デザイン指示: アプリ一覧・操作 UI（#8）

Claude のチャットに送った指示（アーティファクト「thoth — アプリ管理 UI プロトタイプ」を作成）。デザインの参照方法は `CLAUDE.md` の「画面デザインの実装ルール」を参照。

```
ローカルPCのWebアプリを管理・監視するアプリ「thoth」の【アプリ一覧・操作UI】を、Artifactsで新規にUIデザイン(単一のHTML/Reactアーティファクト、モックデータで動作するインタラクティブなプロトタイプ)として作成してください。【前提】ダーク固定のサイバーパンク調(背景 #020618、primary rgb(20,160,230)=シアン系、accent rgb(202,65,34)=オレンジ赤、success=teal、destructive=rose、見出しはOrbitron系+日本語はHiragino Sans/Noto Sans JP)。利用者1名、日本語UI。モバイル(375px幅)とデスクトップ(md=768px以上は固定サイドバー、未満はヘッダー+ドロワー)の両方で主要操作ができること。ナビは ダッシュボード / アプリ / ログ / リソース。【必要な画面・要素】1)アプリ一覧: 各アプリのカード(名前、説明、全体状態バッジ=実行中/停止中/一部起動/操作中/エラー)、サービス一覧(サービス名、kind、状態=running/stopped/unsupported、PID、依存関係)。unsupportedのサービスは操作ボタンを無効化し理由を表示。 2)操作: アプリ単位とサービス単位の 起動/停止/再起動 ボタン。状態に応じて有効・無効を切替(実行中なら起動不可など)。操作中はスピナーとボタン無効化(busy表示)。操作結果は成功/失敗のトースト+カード内メッセージで反映。 3)起動モード選択: local / lan / vpn のセグメント切替。選択不可のモードは無効化し理由(例:環境変数未設定)をツールチップ/補足表示。起動中のサービスがあるときは切替不可(「停止してから切り替えてください」)。 4)一括操作: 全アプリの 一括起動/一括停止/一括再起動 と失敗時の挙動(続行 continue / 中断 abort)の選択。結果は全体ステータス(ok/partial/failed)とアプリごと・サービスごとの結果(ok/skipped/error、メッセージ)をパネルまたはシートで表示。 5)誤操作防止: 停止・再起動・一括操作は確認ダイアログ(対象アプリ数/名前と影響を明記、危険操作はdestructive色、キャンセルが既定フォーカス)。 6)状態の定期更新: 一定間隔(例5秒)で自動更新。最終更新時刻、手動更新ボタン、更新の一時停止切替、更新失敗時の警告バナー。 7)画面状態: 通常 / 読み込み中(スケルトン) / 空(アプリ未登録、config/apps.yamlへの案内) / エラー(バックエンド接続不可、再試行ボタン)。 8)設定再読込ボタン(POST /api/config/reload)。 9)アクセシビリティ: キーボード操作、focus-visible、色だけに頼らない状態表示(アイコン+文言)、タップ領域44px以上。【出力】モックデータ(例: 5アプリ、うち複数サービス持ち、実行中・停止中・エラー・操作中・unsupportedを含む)で実際にボタン操作・確認ダイアログ・トースト・モード切替・一括操作結果が動く状態にしてください。画面状態(空/読み込み/エラー)を切り替えて確認できるデモ用スイッチも付けてください。
```

## 実装時の注意

- モックのダミーデータ、デモ用スイッチ（画面状態の切替・失敗の強制）、ログ・リソースの仮画面は実装に含めない。
- ダッシュボードはモックでは状態の集計表示のみ。

## 追記: 一括操作の完了通知（#54）

デザインを修正してください。一括操作（一括起動・一括停止・一括再起動）が完了したとき、結果は右側の結果ドロワー（ResultSheet）だけで表示し、完了トースト（「一括停止: 成功」「N アプリ成功 / M アプリ失敗」など）は出さないようにしてください。具体的には runBulk 完了時の toast(...) 呼び出しを削除します。ok / partial / failed のどの結果でもトーストは出さず、ドロワーのみで結果を示します。一括操作の API 呼び出し自体が失敗した（ネットワークエラーなど）場合のエラートーストは残します。個別アプリ・個別サービス操作、設定再読込、起動モード切替などのトーストは変更しないでください。それ以外のデザインは変えないでください。
