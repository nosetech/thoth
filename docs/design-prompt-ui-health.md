# デザイン指示: ヘルスチェックの状態・履歴表示（#12）

Claude のチャットで、既存のアーティファクト「thoth — アプリ管理 UI プロトタイプ」（#8）に追記・更新するための指示。デザインの参照方法は `CLAUDE.md` の「画面デザインの実装ルール」を参照。更新後は `CLAUDE.md` のデザイン URL・ファイル一覧も更新する。

```
既存のアーティファクト「thoth — アプリ管理 UI プロトタイプ」の【アプリ一覧】に、ヘルスチェックの状態表示と履歴表示を追加してください(既存のレイアウト・配色・操作は変えず、追記のみ)。【前提】backendは各サービスを定期チェックし、状態を4種類で返します: healthy=正常 / unhealthy=異常(連続失敗) / starting=起動中(起動直後の猶予内の失敗) / unknown=不明(結果なし・チェックが古い・停止中でチェックしていない)。unsupported(scheduled等)のサービスはチェック対象外で、状態を出しません。各状態には最新の結果メッセージ(例: 「127.0.0.1:3000 に接続できます」「HTTP 500(期待: [200])」)と最終チェック時刻が付きます。履歴は新しい順で ok(成功/失敗)・メッセージ・時刻の一覧で、保持期間(既定7日)を過ぎたものは消えます。【必要な要素】1)サービス行にヘルス状態バッジ(正常/異常/起動中/不明。色だけに頼らずアイコン+文言)。既存の running/stopped とは別軸なので、両方が読み取れる配置にする。最終チェック時刻と最新メッセージを補足表示(長ければ省略しツールチップ等)。 2)アプリカードの全体状態への反映案: いずれかのサービスが異常ならカード上で気づける表示(既存の全体状態バッジを変えるか、別の警告表示かを提案して実装)。 3)履歴表示: サービスごとに「履歴」を開く導線(シート/ドロワー/展開のいずれか。既存のResultSheetとの整合を優先)。直近N件の成功/失敗の推移を簡易に視覚化(例: 成功・失敗を並べたストリップ)+時刻付きの明細リスト。履歴が空のときの空状態(「まだチェック結果がありません」)。保持期間の注記(「7日より古い履歴は自動で削除されます」)。 4)状態の取得失敗時(ヘルス取得だけ失敗)は、一覧の操作は継続でき、ヘルス表示のみ「取得できません」とする。 5)既存の定期更新(5秒)に同期して状態が更新される。更新中のチラつきを避ける。 6)モバイル(375px)とデスクトップの両方、アクセシビリティ(キーボード操作・focus-visible・タップ領域44px以上)を満たす。【出力】既存のモックデータに、正常・異常・起動中・不明(停止中)・履歴あり/なしの各ケースを足し、バッジ・履歴の開閉が実際に動く状態にしてください。
```

## 実装時の注意

- モックのダミーデータ・デモ用スイッチは実装に含めない。データは `GET /api/service-health` と `GET /api/service-health/{app_id}/{service_id}/history` から取得する。
- 見た目は cosmic-ui のコンポーネントに従う（値はデザインから移植しない）。
