# デザイン指示: 自動再起動の状態表示（#13）

Claude のチャットで、既存のアーティファクト「thoth — アプリ管理 UI プロトタイプ」（#8）に追記・更新するための指示。デザインの参照方法は `CLAUDE.md` の「画面デザインの実装ルール」を参照。更新後は `CLAUDE.md` のデザイン URL・ファイル一覧も更新する。

```
既存のアーティファクト「thoth — アプリ管理 UI プロトタイプ」の【アプリ一覧】に、サービスの自動再起動の状態表示を追加してください(既存のレイアウト・配色・操作は変えず、追記のみ)。【前提】backendは、設定で自動再起動を有効にしたサービスだけを、異常終了やヘルスチェック異常のときに自動で再起動します。手動で停止したサービスは再起動しません。再起動は回数の上限とバックオフ(待ち時間を倍々に延ばす)があり、上限に達しても直らなければ再起動を止めます。APIは自動再起動を有効にしたサービスごとに次を返します: state = watching(監視中) / retrying(再起動を試行中) / gave_up(上限に達して自動再起動を停止) / idle(稼働させない状態=手動停止中など)、attempts(試行回数)、max_retries(上限)、last_attempt_at(最終試行時刻)、next_attempt_at(次の試行予定時刻。retryingのみ)、message(直近の結果。例: 「プロセスが停止したため自動再起動しました(1/5回目)」「再起動を5回試みても復旧しないため、自動再起動を停止しました(原因を確認し、手動で起動してください)」)。自動再起動を有効にしていないサービスは何も出しません。【必要な要素】1)サービス行に自動再起動の表示(アイコン+文言。色だけに頼らない): 監視中=「自動再起動: 有効」程度の控えめな表示、再起動中=「再起動を試行中 2/5回」+次の試行予定時刻、上限到達=「自動再起動を停止(上限5回)」を目立つ警告として表示し、メッセージ全文を見られる(長ければ省略しツールチップ等)。idleは出さないか控えめに。 2)上限到達のサービスがあるアプリは、アプリカード上で気づける警告表示(既存のヘルス異常アラートと並べるか統合するか、提案して実装)。警告には「原因を確認して手動で起動してください」という行動の案内と、既存の「起動」ボタンへの導線を含める(手動で起動すると上限到達の状態は解除される)。 3)上限到達の状態からの復帰: 手動で起動すると警告が消え通常表示に戻ることを、モックで操作して確認できるようにする。 4)状態の取得失敗時(自動再起動の取得だけ失敗)は、一覧の操作は継続でき、この表示のみ「取得できません」とする。 5)既存の定期更新(5秒)に同期して更新され、チラつかない。 6)モバイル(375px)とデスクトップの両方、アクセシビリティ(キーボード操作・focus-visible・タップ領域44px以上)を満たす。【出力】既存のモックデータに、監視中・試行中・上限到達・自動再起動なし・手動停止中のケースを足し、上限到達の表示と手動起動での解除が実際に動く状態にしてください。
```

## 実装時の注意

- モックのダミーデータ・デモ用スイッチは実装に含めない。データは `GET /api/auto-restart` から取得する。
- 見た目は cosmic-ui のコンポーネントに従う（値はデザインから移植しない）。
