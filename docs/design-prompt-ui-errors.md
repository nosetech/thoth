# デザイン指示: エラー検知画面（#16）

Claude のチャットで、既存のアーティファクト「thoth — アプリ管理 UI プロトタイプ」（#8）に追記・更新するための指示。デザインの参照方法は `CLAUDE.md` の「画面デザインの実装ルール」を参照。更新後は `CLAUDE.md` のデザイン URL・ファイル一覧も更新する。

```
既存のアーティファクト「thoth — アプリ管理 UI プロトタイプ」に【エラー検知画面】を追加してください(他の画面・既存のレイアウト・配色・操作は変えず、追記のみ)。ナビに「ERRORS」を LOGS の直後に追加し、そこに画面を割り当てます。【前提】backend は各サービスの log_paths を常時監視し、アプリごとに YAML で定義した「エラー検知ルール」(ログレベル条件と正規表現パターン、対象サービスの限定、除外パターン、重要度 error/warn)に一致した行を「検知結果」として DB に保存します。ログ形式はアプリ・サービスごとに異なるため、レベルを取り出すパーサ設定(正規表現と、レベル文字列→ERROR/WARN/INFO/DEBUG の対応表)も YAML で指定します。ルールの編集は YAML で行い、画面では参照のみです(編集フォームは作らない)。検知結果は「確認済み」にでき、確認済みは既定で非表示です。【必要な要素】1)概要: 未確認の検知件数(重要度 error / warn 別)、最終検知日時、アプリごとの未確認件数。 2)検知結果の一覧(新しい順): 検知日時(相対+絶対)、重要度バッジ(アイコン+文言、色だけに頼らない)、アプリ名/サービス名、ルール名、ログファイル名、該当行(等幅、長い行は省略して展開可能)、確認状態。各行から「ログで確認」で LOGS 画面へ遷移(そのアプリ・サービス・ファイルを選択した状態)。 3)フィルタ: アプリ、サービス、ルール、重要度、「確認済みも表示」。件数表示。 4)確認操作: 行ごとの「確認済みにする」と、表示中の未確認をまとめて「すべて確認済みにする」(確認ダイアログ付き)。 5)ルール一覧(タブまたはセクション): アプリごとに、ルール名・ID、重要度、レベル条件、パターン、除外パターン、対象サービス、適用中のパーサ(既定の自動推定 or 正規表現)を表示。ルール未設定のアプリは「既定ルール(ERROR レベルを検知)」と表示、検知を無効にしたアプリは「検知しない」と表示し、設定は config/apps.yaml で行う旨の案内を出す。 6)ダッシュボードの「要対応」に、未確認の検知があるサービスを1行ずつ追加(件数・最新の該当行の抜粋付き。押すと ERRORS 画面へ遷移しそのサービスで絞り込み)。 7)画面状態: 通常 / 読み込み中(スケルトン) / 検知なし(「検知されたエラーはありません」)/ フィルタ結果0件 / 取得エラー(再試行ボタン)/ 監視対象なし(log_paths を持つサービスが無い)。 8)既存の5秒ポーリングに同期して更新(タブ非表示中は停止)。新しい検知が来ても一覧がチラつかない。 9)モバイル(375px)とデスクトップの両方、アクセシビリティ(キーボード操作・focus-visible・ライブリージョンは過剰に読み上げない)を満たす。【出力】既存のモックデータに、deep-tracker / backend の ERROR 連続検知、別アプリの WARN 検知、確認済みの検知、ルール未設定のアプリ、検知無効のアプリ、独自パーサ設定のアプリの各ケースを足し、表示が実際に切り替わる状態にしてください。
```

## 実装時の注意

- モックのダミーデータ・デモ用スイッチは実装に含めない。データは `GET /api/errors`・`GET /api/errors/rules` から取得し、確認操作は `POST /api/errors/ack`。
- 見た目は cosmic-ui のコンポーネントに従う（値はデザインから移植しない）。
